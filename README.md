# 奇妙商店物语 · 小旅馆附属（wss_hotel）

为《奇妙商店物语》1.6.7 新增 **“小旅馆”** 店型的附属 Mod。

- Minecraft **1.21.1** / NeoForge **21.1.251** / Java **21**
- 依赖本体：`wonder_shop_story_core` **[1.6.7, 1.6.8)**
- 不使用 mixin、不反射修改本体；仅通过本体附属 API 与公开策略接口扩展，**不影响存档兼容与既有四类店铺**。

## 玩法概览

| 机制 | 说明 |
| --- | --- |
| 新店型 | 选店列表新增“小旅馆”（难度 3），签约后自动摆放前台收银台与初始床位 |
| 入住登记 | 房客到前台排队，前台接待（收银员岗位）按服务属性计时办理入住 |
| 房间管理 | 房间 = 任意颜色的床 + 床边站位，自动扫描；干净空房数即接待容量 |
| 按时长计费 | 住宿按游戏时间累计晚数（默认 1 晚 = 10000 刻），房客上床就寝 |
| 定价玩法 | 台账页“价目”里按房型定价（1~3000 金），价格影响客流（弹性）与房客评价 |
| 退房结算 | 复用本体账本与 `CUSTOMER_PAID` 事件；比赛日与夜间时段自动上浮，超时 1.5 倍加收 |
| 评价兼容 | 普通房客走本体粉丝/人气体系；特殊房客走 `SPECIAL_REVIEWED` 剧情奖励 |
| 清洁维护 | 退房后房间待清洁；客房保洁员（新岗位）打扫后才可再入住；脏房隔夜可能引发投诉赔款 |
| 早餐加购 | 台账页配置早餐菜单（本体菜品 ×3），房客按概率点单，退房按菜价加收 |
| 经营计划 | “旅行团包房”（5 天客流提升）与“深度大扫除”（立即清空脏房） |
| 旅游联动 | 派员工前往“山间温泉疗养地”，归来次日产生包房客流脉冲 |
| 收益台账 | 房态一览、今日/累计房费、入住率、14 日收入图、最赚钱客房、投诉计数 |

- **诊断增强**：接待门槛行追加 `服务员 雇=X 在店=Y 可派=Z 任务=N 需求=M 货架=K 缺货层=L`——服务员不动/不补货时看这行即可定位（雇员不足/未到店/未排班/无任务/缺货层为零各对应不同环节）。

### 1.6.2（性能优化）

- **货架渲染推送去重**：此前每 10 刻对每个货架无条件写入方块实体（触发本体渲染同步与网络更新），现改为内容签名比对，仅在商品/库存实际变化时写入——多货架旅馆的持续性开销大幅下降。
- **全量扫描校验降频 + 玩家邻近门控**：修复 WorldEdit 不触发缓存失效的校验扫描从每 30 秒降为每 2 分钟，且仅当有玩家在店铺附近时执行（无人查看容量时跳过）。
- 其余热路径（订单循环/保洁/服务/派单）本轮审阅后确认为小集合遍历，未做改动。

### 1.6.0（“旅馆扩展”创造页签）

- **创造模式物品栏新增“旅馆扩展”页签**：收纳附属自有内容——客房门牌（挂墙四态房态显示，放置时自动绑定最近客房，拆除自动解绑）、房卡（退房 10% 概率掉落的纪念品，含店名）、大堂饮品台（房客退房前顺路购买，单价台账可改）。
- 相关功能管线（绑定/同步/掉落/购买）已随 1.4.x–1.5.x 就位，本版补齐注册与创造页签。

### 1.5.3（岗位容量不涨修复）

- **修复：多放货架后服务员/补货员容量上限不增加**——诊断行新增 `扫货架=X 容量 服=A 补=B`（扫描到的货架数与两类岗位当前容量上限）；并每 30 秒做一次全量扫描校验，发现世界内货架/客房数与设施快照不一致（WorldEdit 等非常规改块不触发本体失效监听时）自动强制重扫，容量即恢复。
- 若日志显示 `扫货架` 数量正确而容量仍不对，发日志再查。

### 1.5.2（新增补货员岗位）

- **新增“补货员”岗位**（本体便利店内置 STOCKER）：货架补货职责从服务员移交补货员——补货员把配置好的商品补满货架（免费）；服务员专注为点单房客送货（补货员闲置时也会顶班补货）。
- 岗位容量：服务员≈每 4 货架 1 人（送货）、补货员≈每 3 货架 1 人（补货）；两类岗位都不是必需——不雇只影响对应功能，不会卡接待。
- 诊断行新增 `补货员 雇/在店/可派/任务` 明细。

### 1.4.9（服务员兼任补货员）

- **服务员岗位覆盖补货员职责**：本体工作方块检查要求货架空层时有“补货员”在编，旅馆店型下自动把在编服务员计入补货员（WorkstationHealth.staff Mixin），玩家只雇服务员即可覆盖货架零售，不再被要求另雇补货员。

### 1.4.8（回退客房升级入口）

- **按用户要求回退**：“客房升级”恢复为左侧导航按钮；店铺配置页签方案（ShopConfigurationMixin）整体移除——F6 打不开界面的最后一环是该 Mixin 的 APPLY 失败（`setOnTabSelected` 为链式方法返回 `TabView`，@Redirect handler 返回类型必须同为 `TabView`，此前写了 void），连续三轮签名问题后放弃页签方案。
- 数据刷新修复（升档即时回显/价目回包通知）保留。

### 1.4.7（@At 描述符终修）

- **修复：页签点击仍崩溃**——`@At` 匹配需要**完整方法描述符（含返回类型）**：字节码里 `setOnTabSelected` 的指令返回 `TabView`（链式调用），此前写的 `)V` 不匹配导致重定向仍未命中。现两个注入点的 owner 与描述符均从本体字节码（javap 反编译 ShopConfiguration 构造器）逐字符核对：`select(I)V` 与 `setOnTabSelected(Ljava/util/function/Consumer;)Lcom/lowdragmc/lowdraglib2/gui/ui/elements/TabView;`，owner 均为接收者静态类型 SproutTabView。

### 1.4.5（页签点击崩溃根修）

- **修复：点“客房升级”页签崩溃**——`setOnTabSelected` 声明在 ldlib2 父类 `TabView`，调用点指令 owner 是父类，此前 @At 目标写的子类导致该重定向静默未命中（页签出现了但回调没被包装），点击时越界异常从界面事件分发直抛崩溃。现 @At 目标改为父类 `TabView`，回调包装真正生效：点击页签 → 切回上一个安全页签 → 打开客房升级界面。

### 1.4.3（页签点击修复 + 数据刷新）

- **修复：点“客房升级”页签导致店铺菜单异常**——1.4.2 的回调包装因 ldlib2 父类签名未知未生效，点击追加页签的越界异常直接进入界面事件栈。现改为运行时自探测：枚举 setOnTabSelected 参数接口与已注册回调字段，动态 Proxy 包装；点击追加页签时先切回上一个安全页签再打开升级界面，异常不再进入界面事件栈。
- **修复：升级/价目操作后数值不刷新**——升级结果回包的房态来自 20 刻才刷新的房态缓存（回包仍是旧档位），现升级时即时同步缓存；台账数据到达时通知客房升级页重置价目缓存。

### 1.4.2（客房升级入口调整）

- **“客房升级”移入店铺配置页签栏**（合作邀请右侧）：点击页签直接打开客房升级界面（保持店铺会话，返回后回到店铺配置）。
- 侧边导航的“客房升级”按钮同步移除，功能不受影响；通过新增的客户端 Mixin 实现（ShopConfiguration 页签栏追加，对本体其它店型零影响）。

### 1.4.1（备货同款 UI）

- **旅馆备货改用本体同款界面**：店铺配置出现便利店同款“备货”页签（RetailStockPanel），右键货架也可直接打开；货架配置/库存存入本体零售数据层（RetailState），与便利店数据链路完全同源。

## 从源码构建

前置：Java 21 JDK。工程使用 Gradle Wrapper（`gradlew.bat`）。

```powershell
cd wss-hotel-addon
.\gradlew.bat build
```

产物：`build/libs/wss-hotel-addon-1.2.0.jar`。

### 网络 / 缓存说明

- `gradle.properties` 中已配置本机代理（`127.0.0.1:7890`）用于下载 NeoForge / Minecraft 工具链；**无需代理时可注释掉对应四行**。
- 工具链下载完成后 `gradlew.bat build --offline` 可完全离线构建（Gradle 缓存位于 `C:\Users\<用户>\.gradle\caches`）。
- `libs/wonder_shop_story_core-1.6.7.jar` 是**编译依赖**，请勿放入游戏 `mods`。

## 安装

1. 安装《奇妙商店物语》1.6.7 整合包。
2. 退出游戏，把 `wss-hotel-addon-1.2.0.jar` 放入 `mods`（客户端与服务端都要装，版本一致）。
3. 备份存档后再用于正式经营。

## 真机测试清单（发布前建议逐项过）

**二期增量**：
1. 台账头部显示等级/称号与当前节气（淡/旺标签）；节气切换当日客流与房价按倍率表变化。
2. ≥3 晚订单结算 9 折（报价、账本 reason、超时部分不打折）；钟点房不受折扣影响。
3. 住宿中房客提出需求（头顶状态"提出需求：……"）→ 保洁/前台上门完成 → 满意度结算 +3/次 + 小费；整晚无人处理 → 台账"怠慢"+1、结算 −2。
4. 台账"连锁"视图：两家以上旅馆时聚合总数与排行正确，未加载门店可读。
5. 门牌放置自动绑定最近客房，四态贴图随房态变化；拆床/拆门牌后无残留报错；重进世界绑定恢复。
6. 摆放饮品台后房客退房顺路购买（OPERATE 动画→账本"含饮品"→台账饮品收入）；无可达柜台不阻塞退房。
7. 房卡掉落（默认 10%）含店铺名；台账价目页可改饮品价（50~2000）。
8. 2 级前豪华档房间按舒适价计费；升级后恢复豪华价。

**基础链路**：

1. **全链路**：签约→初始床位/收银台生成→雇佣前台+保洁→房客登记入住→就寝（含躺卧姿态）→退房结算（飘字/账本/日结通知）→保洁打扫→再次入住。
2. **定价**：台账页修改三档价目→客流随价格变化；设为上限 3000 观察客流明显下降。
3. **旺日/夜间**：比赛日当天客流与房价上浮；夜间入住加价。
4. **钟点房**：开启后房客选择钟点房，半价结算。
5. **早餐**：配置早餐菜单→房客点单→退房加购金额正确。
6. **特殊房客**：老周/林小姐到访（林小姐需存在豪华床位）→好评触发 120 金答谢。
7. **经营计划**：旅行团包房（需≥3 房）生效期间客流上升；深度大扫除清空脏房。
8. **投诉**：脏房放置过夜→出现投诉赔款负向流水、当日评价减分。
9. **边界**：退房前拆床/拆收银台/解雇保洁→订单正常收尾无卡死、无永久占用。
10. **存档**：保存→重进世界，在住房客、台账数据、价目配置完整恢复；旧 1.0 存档升级后自动迁移。
11. **双端**：客户端与服务端同装同版本可连接（内容指纹一致）。

## 卸载与兼容

- 卸载附属后，小旅馆店型显示为“缺少附属”占位，挂载数据（住宿/台账/价目）保留在存档中，重装即可恢复。
- **素材声明**：`textures/entity/special/` 下的两张特殊房客皮肤为本体素材占位，正式发布前请替换为有授权的自有素材。
- 发生行为变化时请递增版本号，并保证客户端与服务端安装同一份产物。

│  ├─ HotelProducts.java   空商品目录

│  └─ HotelWorkPolicy.java 保洁任务上报与断点恢复
├─ net/HotelPackets.java   台账（读缓存）+ 价目/早餐配置包
└─ client/                 仅客户端：导航入口 + 台账界面（查看/价目编辑）
